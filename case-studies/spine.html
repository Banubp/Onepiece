01

Problem and thesis

Why naming a principle is not the same as solving the case.

From principle theatre to causal reasoning

“Use Hick’s Law” sounds rigorous but does not explain the mechanism, predicted behaviour or business consequence.

Product critique often jumps from an interface symptom to a familiar law and then to a redesign. The first plausible explanation becomes the solution, while contradictory evidence and system-level leaks remain invisible.

The case is solved only when the mechanism changes and the evidence survives competing explanations.Framework thesis
Failure 01

Principle matching

A screen is labelled with a law without tracing causality.

Failure 02

Single-hypothesis bias

The first believable story becomes the direction.

Failure 03

Local optimisation

A usability gain creates a trust or value leak elsewhere.

Failure 04

Outcome amnesia

Failed predictions do not update the framework.

04

Six-pass Audit Engine

A repeatable path from observation to defensible intervention.

Reasoning workflow

Each pass produces a distinct artefact so interpretation cannot quietly become fact.

Pass one

Record facts

Capture observable state without recommendation or causal story.

Pass two

Map mechanisms

Identify multiple forces that could plausibly create the behaviour.

Pass three

Locate leaks

Trace lost user value, captured value and system consequences.

Pass four

Compare hypotheses

Score support, contradiction, missing evidence and confidence.

Pass five

Order experiments

Choose the test with the highest expected information gain.

Pass six

Write the decision

Attach intervention, owner, evidence, falsifier and review date.

05

The Forge

Governance that stops the library becoming bloated.

Five admission gates

A new principle must earn its place by improving reasoning coverage.

Gate 01
Distinct mechanism

Does it explain something the library cannot?

Failure result

Merge with the closest existing principle.

Gate 02
Falsifiable claim

Can an observation prove it wrong?

Failure result

Reject decorative authority.

Gate 03
Practical instrument

Can a team use it to decide?

Failure result

Keep as context, not a tool.

Gate 04
Boundary clarity

Are context and inversions explicit?

Failure result

Return for research.

Gate 05
Evidence quality

Is support stronger than repeated citation?

Outcome

Admit, merge or reject.

07

Validation and learning loop

How the framework compounds instead of becoming static doctrine.

Measure reasoning quality

Every result updates confidence, boundaries and the next investigation.

TraceabilityAnother person can reconstruct the evidence and decision.
DiscriminationThe experiment separates competing explanations.
TransferThe mechanism survives relevant contexts and states.
LearningFailed predictions update confidence and the library.
The daylight test

If the reasoning cannot be inspected, contradicted and revised by another person, it is not ready to guide an intervention.

08

Reflection and next step

From an analyst’s framework to an autonomous reasoning system.

Key learning

A bigger library is not a better framework. Better discrimination is.

Expansion is now paused. The next phase is building Spine with memory, versioned evidence files, an LLM and an orchestrator that can improve the framework over time without invisibly rewriting its standards.
