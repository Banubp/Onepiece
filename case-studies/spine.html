01

Problem and thesis

Most design audits identify surface issues without connecting them to behaviour, value or decision priority.

From subjective critique to decision intelligence

A comment such as “the hierarchy feels weak” is not yet an actionable finding. Teams also need the evidence, affected users, mechanism, severity and likely consequence.

Conventional reviews often mix observable facts with interpretation, apply familiar principles without checking context, and produce long issue lists without explaining what should change first. The result can look rigorous while leaving teams to make the actual decision themselves.

Spine is designed to turn a screen, Figma file or product URL into an inspectable chain of reasoning—from visual evidence to behavioural risk, value leak and a prioritised recommendation.

Research foundation

Literature synthesis + audit taxonomy

  • Information architecture, typography and visual perception

04

Six-pass Audit Engine

A repeatable path from observation to defensible intervention.

Reasoning workflow

Each pass produces a distinct artefact so interpretation cannot quietly become fact.

Pass one

Record facts

Capture observable state without recommendation or causal story.

Pass two

Map mechanisms

Identify multiple forces that could plausibly create the behaviour.

Pass three

Locate leaks

Trace lost user value, captured value and system consequences.

Pass four

Compare hypotheses

Score support, contradiction, missing evidence and confidence.

Pass five

Order experiments

Choose the test with the highest expected information gain.

Pass six

Write the decision

Attach intervention, owner, evidence, falsifier and review date.

07

Learning architecture

How Spine is intended to improve without silently rewriting its own standards.

Planned system behaviour · not reported performance

The learning module will retain evidence, corrections and framework changes as versioned records that remain visible to human review.

The daylight rule

If another person cannot inspect, challenge and reverse a framework change, the system must not learn from it automatically.

08

Current build and next step

Moving from a documented framework to a working AI design-audit system.

Build priority

The value of Spine will come from the quality and traceability of its diagnosis—not the size of its principle library.

Framework expansion is paused while the first product stage is built: accepting Figma links, design URLs and screenshots; inspecting visual and behavioural quality; generating heatmaps and graphs; and returning prioritised, evidence-linked upgrade guidance. Memory, versioned files, an LLM and an orchestrator will be added behind explicit review boundaries.
