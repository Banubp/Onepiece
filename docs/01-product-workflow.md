# Portfolio Product Workflow

## Goal

Help a recruiter or design lead understand Banu's product-design ability within 30 seconds, reach a case study within one interaction, and contact him without searching.

## Delivery stages

1. Content audit — recover factual case-study and profile content; reject legacy frontend code and styling.
2. Journey definition — map recruiter scan, deep case-study review, CV download, and contact paths.
3. Information architecture — Hero → Selected work → Capability → About → Contact.
4. Wireframes — establish hierarchy and mascot-safe zones on desktop and mobile.
5. Visual system — define tokens, typography, spacing, surfaces, motion, and interaction rules.
6. Prototype — implement semantic responsive UI plus mascot state machine.
7. Quality gate — test keyboard access, responsive breakpoints, reduced motion, links, and contact feedback.
8. Release — commit the verified project to `Banubp/Onepiece` on `main`.

## Success checks

- Role and specialism are understood from the first viewport.
- Selected work is visible at or immediately below the fold.
- Stories communicate problem, decisions, and outcome—not only screens.
- Every click has visible feedback.
- Mascot strengthens identity without competing with content.
